**Enforcement is three-layered and each layer catches a different failure:**

## The decisions that aren't obvious from the code

- **Cost is computed at write time**, stored as micro-USD `BigInt`. Read-time pricing would make last quarter's spend change when a model gets cheaper. Single division to dollars happens at the API boundary (`summarize.ts:46`).
- **NULL, never 0**, for an unmapped model. A zero sums cleanly and under-reports forever.
- **MOAD auth is inverted**: MOAD holds one Ed25519 private key and signs; each project verifies with the public half committed in `route-factory.ts:94`. That kills credential distribution entirely rather than N shared secrets. `MOAD_AUDIENCE` is the only per-project value; `MOAD_PUBLIC_KEY` is an override for staging or a staged rotation. Fails closed.
- **Tracking never breaks the call it tracks.** `createAiTracker` swallows everything on the recording path, including a bug in a caller's own `extract`. The two failure-isolation tests in `ai-usage.test.mts` are the ones that matter if anyone refactors it.

## The trap the code exists to contain

`usage.ts` — the three providers disagree on whether prompt tokens already include cached tokens. Anthropic excludes (add all four buckets), OpenAI and Google include (subtract, or every cache hit gets billed twice). Get it wrong and the totals are plausible, self-consistent, and wrong. Also handled: long-context `overrides` tiers, merged field-by-field so an override that only declares `prompt` doesn't blank the completion rate; and cached tokens count toward the threshold, since the provider charges for the window, not what changed in it.

**"what is service tier?"**

Providers sell the same model at different prices depending on how you call it. Three values in our enum:

- `standard` — a normal synchronous call.
- `batch` — you submit work and collect it later, typically within 24 hours. Roughly half price. OpenRouter lists it as a separate entry (`anthropic/claude-opus-5:batch`), which is why `openRouterSlug()` appends the suffix rather than applying a multiplier.
- `fast` — priority routing. No provider charges a premium for it today, so it prices identically to standard. It's in the enum so that if one ever starts, it's a one-line change instead of a schema migration.

It matters for Hussain because 10,000 batch calls and 10,000 standard calls on the same model are genuinely different money. Without the column he'd have no way to tell them apart, and the batch ones would look mysteriously cheap.

**"why micro USD?"**

Floats can't represent most decimal fractions exactly. `0.1 + 0.2` is `0.30000000000000004` in JavaScript and in Postgres `double precision`. On one row that's invisible. Summed over a few million rows it drifts, and a spend total that disagrees with itself between two queries is worse than useless.

So money gets stored as an integer, and the only question is which unit. Cents is too coarse: a single cheap call can cost $0.000003, which rounds to 0 cents, and a table full of zeros is a table that says you spent nothing. Micro-USD (millionths of a dollar) keeps six decimal places of precision, stays an exact integer, and sums without drift. Divide by 1,000,000 once at the very end to display dollars.

It also happens to answer Hussain's cents-versus-dollars worry more firmly than either option he offered. There's no decimal point anywhere in the pipeline to get misplaced, and the column name says the unit, so a repo storing the wrong thing is visible at a glance rather than 100x silently wrong.

One caveat I left a `ponytail:` comment about in `pricing.ts`: a call of a handful of tokens at the cheapest cache-read rate can round below one micro-dollar and land at 0. Fine for aggregates, worth knowing if per-call precision ever matters.

It's a delete job plus two column changes, but two steps in it are where a repo will actually get hurt, so most of the prompt weight is there:

**The `model` backfill.** New rows store slugs, old rows store provider ids, and every rollup then double-counts the same model under two names. Nothing errors. I gave it the `UPDATE ... FROM (VALUES ...)` shape plus a cheap verification: slugs contain a `/` and provider ids don't, so `where model not like '%/%'` finds anything left. Those rows should all have `priced = 0`. One with a cost means the write path and the map disagree, which is a different bug than a missed backfill.

**The `timestamptz` conversion.** `ALTER COLUMN ... TYPE timestamptz` with no `USING` clause interprets existing values in the session's `TimeZone`, which shifts the entire history by a fixed offset if that isn't UTC. Silent, uniform, and invisible afterwards. The prompt insists on the explicit `USING created_at AT TIME ZONE 'UTC'` and tells the agent to confirm the writer really was storing UTC first.
