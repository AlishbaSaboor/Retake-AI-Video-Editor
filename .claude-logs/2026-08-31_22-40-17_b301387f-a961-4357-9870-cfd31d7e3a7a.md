**1. CI script-injection fix — security (`ci.yml`)** — *from hiring*
The template interpolated `${{ github.head_ref }}` straight into a `run:` shell in the `migrations` job, which holds `contents: write` + the migrations token. Branch names allow `;`, `$`, backticks — so anyone who could push a branch had arbitrary code execution with a write token. Now passed via a `HEAD_REF` env var. Also made the auto-migration commit subject **static** (`chore(db): add generated migration`) — a second real bug: a long branch name breached the 72-char header limit `check-commit-message.mjs` enforces, which would fail the push.

**2. Node 20 → 22 in CI (`ci.yml`, `deploy-migrations.yml`) + `engines.node` (`package.json`)** — *convergent, all three*
Root cause they all hit: on Node 20, pnpm's "Unsupported engine" warning bleeds into `generate-migration.mjs`'s captured stdout and corrupts `migration.sql` (`syntax error at or near "WARN"`); Node 22 also unblocks native TS test tooling. **3. Session-cookie options loss — security/correctness (`src/proxy.ts`)** — *convergent: seo fixed, hiring documented*
When copying Supabase's refreshed `Set-Cookie` onto the next-intl response, the template copied only `(name, value)` — dropping `httpOnly`/`secure`/`sameSite`/`maxAge`/`path` and downgrading the refreshed session cookie. Now copies the whole cookie object.

**4. GitHub App token for migrations (`ci.yml` + `docs/CI_CD_SETUP.md`)** — *from seo*
The template's *docs* recommended `actions/create-github-app-token`, but the *workflow* never wired it.
