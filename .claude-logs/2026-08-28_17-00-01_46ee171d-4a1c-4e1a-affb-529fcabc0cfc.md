Done. I built your event taxonomy into the template as a typed instrumentation layer, wired into the PostHog setup that was already here. Everything passes lint, typecheck, env-check, format, and a production build.

## What landed

**The taxonomy as code** — `src/lib/analytics/events.ts` is the single source of truth. Your 6 rules are enforced at the type level, not just documented:
- `object_action` / `snake_case` / past-tense names live in one `ANALYTICS_EVENTS` const.
- **No variables in names** — names are fixed literals; the only assembled ones (`payment_succeeded`, `notification_sent`) come from closed enums.
- **No PII / no free text** — there's deliberately no free-text `string` field in any event contract. `field_changed` records *that* a field changed, never its value.
- **Common attributes defined once** — page/session/entity ids here, user attributes in attribution/identify.

**Attribution** — `attribution.ts` captures UTM on first load as first-touch (set-once) person props + super props, derives `user_source` (internal vs external), and adds `app_version`. `os`/`device`/`country` are left to PostHog's autocapture rather than reimplemented. `identify.ts` handles `identifyUser`/`resetAnalytics`.

**PostHog wiring** — `AnalyticsProvider` (mounted in the root layout, replacing the old `PostHogPageview`) fires `app_opened` once per session, runs attribution, and emits both `$pageview` and taxonomy `page_viewed` on route change.

**Client + server APIs** — strict typed `track()` / `trackServer()` (unknown name or wrong prop shape = compile error) with a `capture()` escape hatch, plus wrappers for every event. `error_shown` auto-fires from `captureClientError` (always) and `captureError` (when given a `distinctId`), so it ties into the existing error system instead of duplicating it.

**Auto-capture helpers** — `<TrackImpression>` (IntersectionObserver → `element_viewed`), `useTrackedField` (`field_changed`), permission funnel wrappers.

**Governance** — `docs/rules/analytics.md` (the 6 rules, file map, catalog, "adding an event" recipe) linked into `AGENTS.md`, so every agent follows it. `NEXT_PUBLIC_APP_VERSION` added to `env.ts` + `.env.example`. A worked `/analytics-demo` page exercises the whole funnel end-to-end as a reference to delete.

## Two things worth your call
- **`payment` is the only process in `ANALYTICS_PROCESSES`** — a placeholder so the mechanism has an example. Add your real backend flows (KYC, withdrawal, etc.) there before instrumenting them.
- **`notification_*` / comms events** exist as server helpers but nothing fires them yet — they need a comms system to hook into, which this template doesn't have.
